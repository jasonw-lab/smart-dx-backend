Smart DX Backend API インタフェース設計書

この設計書の読み方

対象範囲

Property・System・Retail の公開 Controller を対象とします。Actuator、Swagger/Knife4j の UI、静的配信物は業務 API カタログの対象外です。

詳細スキーマの確認先

起動中の環境では http://localhost:8080/doc.html（Knife4j）または /v3/api-docs で、DTO/VO の全フィールドと Swagger 注釈を確認します。本書では連携時に重要な入力・応答型・境界条件を優先しています。

ベース URL　ローカル統合アプリ: http://localhost:8080 ／ nginx 経由: http://localhost。本書のパスは原則としてベース URL からの絶対パスです。

共通インタフェース

通信規約

文字コードUTF-8
JSONContent-Type: application/json
ファイル送信multipart/form-data。ファイル部品名は各 API の表に記載。
日時日付のクエリ値は YYYY-MM-DD。日時の JSON 表現は各 DTO/VO の Spring 設定に従う。
ページングPageResult は data.list と data.total を返す。page の起点は各 API の既定値に従い、Property は原則 0 起点。

標準成功応答

{
  "code": "00000",
  "msg": "success",
  "data": { "...": "API 固有の値" }
}

更新・削除など値を返さない操作は data: null になり得ます。ページング応答の data は { list: [], total: 0 } です。

HTTP ステータスの扱い

ステータス利用箇所クライアントの扱い
200通常の取得・更新・削除応答本文の code と data を確認する。
202物件登録、物件一括取込ジョブ作成受付完了のみ。返却されたジョブ参照を使い、取込ジョブ API で進捗を取得する。
400 / 401 / 403入力不正、未認証、権限不足入力を修正、再ログイン、または必要な権限を確認する。メッセージ・例外表現は共通例外処理に従う。
404 / 409 / 422対象なし、更新競合、処理不能な業務状態操作対象・楽観ロック値・業務状態を再取得して判断する。

認証・認可・マルチテナント

認証

保護された API には次のヘッダーを付与します。

Authorization: Bearer <accessToken>

認証不要は認証 API、一部の物件検索、旧類似物件検索、非本番プロファイルのテスト設定です。カタログでは 認証不要 と表示します。

テナントの決定順

  1. JWT の tenant_id claim
  2. X-Tenant-Id ヘッダー
  3. 設定されたデフォルトテナント ID

JWT の値が優先されます。認証済みリクエストでヘッダーだけを変えて他テナントを指定することはできません。

テナント境界　tenant 対象テーブルには MyBatis-Plus のテナント条件が自動付与されます。クライアントは tenant_id を業務リクエスト本文へ埋め込まず、ログイン時の tenantId または認証済み JWT でテナントを確定してください。

権限　System の作成・更新・削除の一部は @PreAuthorize による権限コード（例: sys:user:create）を必要とします。物件登録は ADMIN または FIELD_AGENT ロールが必要です。

API カタログ

検索欄ではパス、操作名、リクエスト型、応答型を絞り込めます。同一行の複数パスは同一の操作契約を表します。先頭の絶対パスに続く /page 等は同じリソースへの相対表記で、/page 併記は互換エイリアスです。

主要モデルとリクエスト例

ログイン

Content-Type: application/json

{
  "username": "admin",
  "password": "********",
  "tenantId": 1,
  "captchaId": "captcha_id_123",

captcha が必須でない設定では、captchaId と captchaCode は省略できます。

物件検索

POST /api/v1/properties/search
Content-Type: application/json

{
  "scope": "published",
  "keyword": "駅徒歩10分",
  "sortBy": "listedDate",
  "orderBy": "desc",
  "page": 0,
  "size": 20,
  "embeddingRef": "短命の画像特徴量参照",
  "topK": 20
}

referenceAsset と embeddingRef は類似画像検索の起点であり、併用しません。size は 1–1000 です。

PropertyLookupReq の主な項目
項目型・制約用途
scopepublished | draft | all（既定 published）検索対象の公開範囲。
keyword文字列、最大200文字全文・属性検索のキーワード。
searchItemsPropertySearchItemsReq詳細な検索条件の入れ物。
sortBy, orderBy既定: listedDate, descソート指定。orderBy は asc | desc。
referenceAsset, referenceFlagアセットキー、main | sub | layout既存画像を起点にした類似検索。
embeddingRef文字列画像特徴量 API で発行された一時参照。referenceAsset と排他。
非同期物件登録・取込の扱い

202 Accepted は登録完了ではなく、バックグラウンド処理の受理を表します。物件登録の PropertyCreateAcceptedVO、一括取込の BulkImportAcceptedVO に含まれる参照値を保持し、GET /api/v1/property-import-jobs/{jobId} で進捗・結果を確認してください。

既存 OpenAPI 定義との整合性

現時点の取り扱い　apps/backend/services/property-be/openapi.yaml は Property の補助資料として残っていますが、実行時の Controller と完全には一致していません。連携仕様の最終確認には起動中の Knife4j / SpringDoc と Controller 実装を使用してください。

差異本書での扱い
OpenAPI のローカル server は localhost:8081統合アプリの実ポート 8080 を採用。
統一類似検索 GET /api/v1/properties/similar が OpenAPI に未掲載Controller 実装に従い掲載。旧 /{propertyKey}/similar は非推奨として明示。
テスト設定の PUT が OpenAPI に未掲載非本番限定 API として GET / PUT の両方を掲載。
物件登録・取込 API の multipart 項目が OpenAPI と Controller で異なるController の必須・任意項目と制約を採用。
